# Decision log

Dated, append-only. Newest at the bottom. Each entry: what was decided and why, so future sessions do not relitigate.

## 2026-08-16/17: Computation

- **OSM as the single road source**, snapshot 2026-08-17. Distances are to mapped ways; unmapped private tracks exist in reality. Neighbouring countries' roads count, so border spots are scored honestly.
- **Two scenarios instead of one**: A (any drivable way, tracks included) answers "how far from anything drivable", B (tracks excluded) answers "how far from real roads". Both are legitimate and they crown different poles, which is the interesting finding.
- **25 m coarse pass + 5 m refinement** (EPSG:3346, EDT then exact vector distances; see README). The published web raster is a separate 50 m grid, small enough to ship (site/data ~5 MB).

## 2026-08-17: Site and hosting

- **Plain HTML/CSS/JS, no build step, vendored Leaflet 1.9.4.** Longevity and zero maintenance beat framework comfort for a site this size; any future session can edit it without a toolchain.
- **Cloudflare Workers (static assets) as primary, GitHub Pages as mirror.** Static serving on Workers is free and unlimited; Pages is the redundancy and the CI exercise. Both deploy from the same repo.
- **Public repo under the personal GitHub account** (donataskasp), with a repo-local git identity so work identity never leaks into commits.
- **workers.dev URL lock-in accepted for now.** A custom domain (~10 EUR/yr) is deliberately deferred until the Europe version makes the project permanent.

## 2026-08-17/18: UI (v2-v5)

- Satellite is the **default basemap** (bogs and forests read better); OSM a click away.
- Map controls live in a **floating top-right cluster** (basemap, bands toggle, legend, selected-spot readout); clicking the brand resets the map; language defaults to the browser (lt if the browser says lt, else en), hash and localStorage override.
- **Mobile (<=720px) collapses the readout into a bottom-anchored pill** above the attribution. Rule established: mobile-only changes must leave desktop byte-identical (verify with sha256 screenshots).

## 2026-08-18: Analytics

- **Three layers, each honest about what it sees**: raw asset requests (volume, sees everyone, coarse), CF Web Analytics beacon (referrers/countries but blocked by Brave/uBlock, treat as a sample), and the **edge logger as ground truth**: the worker writes one Analytics Engine data point per GET of `/`.
- **GDPR by design, not by banner**: no IPs, no raw user agents, no cookies, no unique identifiers. Consequence accepted: we count page loads, not unique visitors. Browser/OS stored as coarse families; referrer stored as www-stripped host only.
- **Beacon kept anyway**: costs nothing and is the only signal for the GitHub Pages mirror, which has no server side.
- **Workers Analytics Engine over a VPS or self-hosted analytics**: free tier (100k writes/day) is ~1000x headroom, no server to babysit, and blockers cannot see server-side logging at all.

## 2026-08-20: Scaffolding before the Europe build

- **The LT-only site is a demo, not a foundation.** The Europe version gets a from-scratch planning pass (superpowers brainstorming); nothing in the current code, data format, or serving setup is sacred. Decided to plan properly first rather than accrete onto the demo.
- **CI deploys Cloudflare on push** (`deploy-cloudflare.yml`, wrangler-action, secrets in repo settings). Replaces manual `wrangler deploy` as the primary path, killing the "pushed but forgot to deploy the primary" failure mode; manual stays as fallback. Both workflows gained post-deploy verify jobs (content-presence only until a version stamp exists).
- **GitHub Issues adopted as the task tracker** with the keenquote discipline: acceptance criteria, `in-progress` label while a session works an issue, search before filing. Labels created: in-progress, dependencies, ci, epic.
- **Keenquote scaffolding reused where it fits**: dependabot (github-actions ecosystem only, no npm by design), docs/OVERVIEW.md as the re-orientation doc, expanded CLAUDE.md working rules, /ship and /session-close local skills. VPS machinery, marketing skills, and daily-log cadence deliberately not copied.
- **Monitoring: UptimeRobot, not a CI canary.** A scheduled workflow that files an issue on failure was considered and rejected: it checks twice a day instead of every 5 minutes, it cannot self-heal (the realistic failures are Cloudflare being down, which we cannot fix, or a bad deploy, which the deploy workflow's verify job already catches), and a GitHub-hosted canary is a poor judge of the GitHub Pages mirror. Two external monitors instead, one per live URL, 5-minute interval, email alerts. Both URLs are monitored because they fail independently and the mirror is the fallback.

## 2026-08-20: Drop the Pages mirror, repo goes private

- **GitHub Pages mirror removed** (site unpublished, `pages.yml` deleted, monitor deleted). It was built as redundancy plus a CI exercise; the exercise is done and Cloudflare now has real CI with post-deploy verification, so what remained was a second URL nobody used (owner: "nobody has that link, and even I never opened it"). Reverses the 2026-08-17 two-target decision. Cloudflare is now the only deploy target.
- **Repo made private.** The 2026-08-17 public-repo decision was made when the repo held a weekend demo with nothing to protect. The Europe build will carry substantially more work and original thinking, and the product being shared is the map and the app, not the source. Dropping Pages removed the only technical blocker (Pages on a free account requires a public repo; Cloudflare deploys from CI with an API token regardless of visibility).
- Consequence accepted: Actions minutes become metered on a private repo (2000/month free, current usage is a few minutes per deploy). The no-secrets-in-repo rule stays in force regardless of visibility.

## 2026-08-20: Drop the CF Web Analytics beacon

- **Beacon removed from `site/index.html`.** Its one unique value was covering the GitHub Pages mirror, which no longer exists, so it was fully redundant with the edge logger. It also undercounted badly (Brave, uBlock, and AdGuard block it, which made the owner's own visits invisible), while the edge logger records country, referrer, browser family, and OS family server-side where no blocker can interfere. Removing it drops one third-party request from every page load and leaves a single honest analytics source instead of three partial ones. Reverses the 2026-08-18 "beacon kept anyway" decision, whose stated reason was mirror coverage.

## 2026-08-20: Europe planning session (spec and plan approved)

Full reasoning in `docs/EUROPE_SPEC.md` and `docs/EUROPE_PLAN.md`; the kickoff brief is `docs/EUROPE_KICKOFF.md`. Numbers were fetched, not guessed: Geofabrik europe 32.4 GB, north-america 18.0 GB; the Europe extract polygon ends at 46.75E; Workers static assets cap at 20,000 files and 25 MiB each; R2 free tier is 10 GB, 10 M reads a month, free egress; this machine is an M4 Pro, 24 GB, 233 GB free.

- **Hero is "poles plus a continental explore layer"**, not poles-only and not explore-first. The per-unit headline numbers are what people repeat; the explore layer ("how remote is my cabin") is the personal, shareable part and the reason to compute the whole continent rather than 45 country runs. Opens on the visitor's own unit from the request's country and region code (never stored), with an opt-in locate-me button. Offline use remains the app's job; nothing in v1 blocks it.
- **Unit = country, main territory only.** Svalbard, Jan Mayen, Franz Josef Land, Novaya Zemlya, Azores, Madeira are masked: a roadless archipelago would top Europe at 100+ km and teach nothing, the European version of the Alaska problem. Microstates stay in. Units are admin-level-configurable so North America ranks states and provinces.
- **Russia: roads count, not a unit.** Owner decision (the war); also the extract only holds a slice west of the Volga, so a real "Russia to the Urals" would need a separate extract and a manual cut, then win by an order of magnitude. The explore layer still covers the slice so the map has no hole, minus a 50 km data-edge band.
- **Turkey and Georgia in whole**, flagged transcontinental; contested borders as mapped in OSM, footnoted. Self-review found their borders with Syria, Iraq, Iran, Armenia, and Azerbaijan are data edges, so those five become road-only supplement extracts (about 1.5 GB), the same trick the LT run used with its neighbours.
- **Scenario A is the headline, B secondary.** A can only under-report; B over-reports wherever a drivable track exists, and "20 km from a road" contradicted by a track is the public failure mode. Physical drivability, not legal access. Water does not block. Explicit tag lists, tested.
- **v1 is a dated snapshot; automated refresh is a parked stage (#13).** Poles move over years, not weeks. When built: Hetzner box from a scheduled workflow, under 1 EUR a run, PR with a diff report, publish on merge only. An unreviewed auto-publish is how a wrong headline goes live, so it never exists.
- **Europe first, portable by construction; North America straight after** (owner: no waiting for a launch; runs are overnight on the Mac). A region is a config file; the coarse projection is a proj string, not an EPSG assumption (the kickoff's parked EPSG:3035-only design is replaced); units per region; no cross-region ranking ever.
- **Architecture: continental 250 m equal-area raster, tiled exact distance transform, branch-and-bound to exact UTM refinement, grayscale class tiles z0-z9 in PMTiles on R2, static Leaflet site on Workers assets.** Rejected: computing in web-mercator tile space (novel margin math where wrong numbers are invisible) and independent per-unit runs (11 billion cells, border seams). Rejected: vector isobands plus MapLibre (map rewrite for no user gain; MapLibre stays the fallback). Tiles carry the raw class value and the browser applies the palette, because a painted palette cannot be read back exactly from a canvas; dark-mode palettes come free.
- **Published data leaves git.** Archives on R2 under immutable snapshot keys, served through the bucket's own hostname (the worker's 100k free invocations a day would die on one busy evening of tile requests); small JSON plus `manifest.json` in git. Publishing is a manifest commit; rollback is a revert. The repo stays private.
- **Accuracy tiers**: poles exact; 50 m detail rasters around the top 10 per unit; 250 m explore layer (about ±0.2 km, shown as "about 1.2 km"). A 100 m continental layer is a one-line config change but roughly 4x the tile storage; deferred until real archive sizes are measured, not refused.
- **Class table**: 254 classes, 50 m steps under 2.5 km, coarser to "240 km or more" (the arithmetic did not reach 250), 254 edge-masked, 255 no-data.
- **Naming parked** (owner wants help later; English-first, short, language-neutral; "Atokiausia Lietuva" survives as the Lithuanian title of `/europe/lt`). **Domain at Hostinger**, nameservers to Cloudflare as the one-time human step. Old worker becomes a permanent redirect so the LinkedIn link never breaks; new Analytics Engine dataset, old one ages out.
- **Validation is a pipeline stage that blocks publishing**: independent geodesic re-check, land and unit membership, data-edge bound, half-cell grid-shift sensitivity, doughnut hole detection, reproduction of Lithuania's published 3.43 km and 6.67 km as the regression test, invariants, and a satellite contact sheet a human reviews in the PR.
- **Tests: pipeline math only**; screenshots for the site. The plan fixes stages, interfaces, named tests, and acceptance criteria and contains no implementation code (owner's rule for the planning session); each executing session writes its own step-level plan.
- **Tracking**: epic #6 with stage issues #7 to #13; `parked` label created for #13. Build on branch `europe`; `main` keeps serving the LT site until the cutover stage.

## 2026-08-20: Stage 1 implementation decisions

Made while turning `docs/EUROPE_PLAN.md` Stage 1 into the step-level plan (`docs/superpowers/plans/2026-08-20-stage-1-pipeline-foundation.md`) and during the first runs on real data. Each bullet is a deviation from or a refinement of the spec.

- **Tiled distance transform: exact below `max_distance_m`, saturated at it; the doubled-overlap loop is kept but bounded.** The spec's "recompute with doubled overlap until no cell is unresolved" does not survive the real frame: the Europe bbox (measured from `europe.poly`, lon -32.7 to 46.75, lat 29.6 to 81.5) contains Atlantic and Arctic tiles more than 1,000 km from any road, so unbounded doubling would need whole-grid windows of 10 GB or more per worker. A cell whose tiled result is at least the overlap has a true distance of at least the overlap, so clamping it to `overlap * res` is correct as "at least this far", and every value below the cap stays bit-identical to the untiled transform. Production sets the initial overlap to `max_distance_m / coarse_res_m` as the spec says, so doubling is only a safety net.
- **Europe `max_distance_m` raised from 150,000 to 250,000.** With saturation at the cap, the cap must be at or above the class table's top edge (240 km, class 253 "240 km or more") so that a saturated cell can never publish as a wrong "about X km". At 250 km the saturated value falls in class 253 by construction. Cost: the frame margin grows from 150 km to 250 km (634 M to 675 M cells at 250 m) and each tile window grows from 5296 to 6096 cells square. No unit pole in Europe comes within an order of magnitude of the cap; the poles stage must still fail loudly if a unit's best coarse value equals the cap.
- **Frame = bbox of the primary `sources` polygons plus `max_distance_m` margin, snapped outward**, reconciling the spec ("extract bbox plus a margin of max_distance_m") with the plan ("union of source polygons snapped outward"). The margin is what brings the supplement roads (Iran, Iraq, Syria, Armenia, Azerbaijan) into the raster without extending the frame to Iran's eastern border; the edge polygon for masking remains the union of sources plus supplements.
- **Snapshot date is the primary file's `Last-Modified` in GMT**, here 2026-08-19 for a file Geofabrik names `europe-260819.osm.pbf` in its md5 file. Geofabrik serves downloads through a 302 to a mirror (ftp5.gwdg.de on 2026-08-20), which honours `Range`; the md5 file names the dated file, so verification compares the hash only.
- **Container runtime on the Mac is colima plus the docker CLI (brew), not Docker Desktop.** Headless, scriptable, no GUI install for the owner, same Dockerfile everywhere.
- **Container base is `ghcr.io/osgeo/gdal:ubuntu-small-3.13.3`, which is Ubuntu 26.04 with Python 3.14 and osmium-tool 1.19; the Mac venv stays on Python 3.12.** GDAL (3.13.3) and osmium (1.19) are identical on both sides, which is what the pipeline's correctness depends on; the Python minor version differs. All pinned wheels install on both, and the suite is green on both. CI runs the tests inside the image, so the container (the future production environment on a rented box) is what CI proves; the laptop venv is the development convenience. Revisit only if a behaviour difference ever shows up.
- **Extract converts GeoJSONSeq in 256 MB chunks merged through a VRT union, and filters each source before merging.** GDAL's GeoJSONSeq driver makes a schema pass and rewinds, and `/vsistdin/` buffers only 1 MB, so the plan's pipe into ogr2ogr stops after about 2,000 features (measured). Worse, the reader holds about 6 bytes of RAM per byte of input: the 37.7 GB Europe highways export killed ogr2ogr twice (SIGKILL after 3 minutes; `ogrinfo` alone reached a 132 GB memory footprint), while a 1.5 GB prefix peaked at 9.3 GB whether or not a spatial index was requested. The file is therefore split at line boundaries into 256 MB chunks, each converted to an unindexed FlatGeobuf with up to 6 ogr2ogr processes in parallel, and the chunks are merged in one streaming pass through an OGR VRT union layer into the final indexed FlatGeobuf (FlatGeobuf to FlatGeobuf costs 0.5 GB per 4 M features). Text and chunks are deleted once the merged feature count matches. Every extract artefact now carries a `<file>.ok` marker so a rerun resumes at the first missing piece instead of repeating 35 minutes of osmium; the second failure had cost exactly that. Filtering each source PBF with one combined osmium expression before `osmium merge` avoids writing a 35 GB merged PBF; the combined filter over the 34.8 GB Europe file took about 3.5 minutes.
- **No spatial index on the road layers in stage 1, and no single FlatGeobuf above 50 M features.** The merged Europe highways layer (101,461,002 features, 24.5 GB, packed R-tree 4.33 GB) came out unreadable in GDAL 3.13.3: header fine, first feature fails with "Invalid size detected" in both read paths, spatial reads empty, while 4 M-feature files are fine. Rather than bet on the exact bug, the extract keeps any layer above 50 M features as unindexed 256 MB chunks behind an OGR VRT union (`<layer>.vrt` is the canonical handle for every layer; small layers still merge into one indexed file behind the same kind of VRT), classify writes `roads_A`/`roads_B` without an index, and gdal_rasterize reads unindexed input in a single pass (its AUTO mode picks the vector-iteration algorithm when the layer has no spatial index, with the raster held in cache). Stage 2 needs bbox queries and chooses its own structure with a measured limit; tracked in #16. Spec 3.2 said "FlatGeobuf with spatial index"; the format stays, the index moves to where it is needed.
